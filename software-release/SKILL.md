# 软件公开发布

把用户指定的软件从本机成果交付为可访问、可下载、身份可核对的公开版本。已经授权且具备条件时实际构建、测试、部署和回读；只有需要新增权限、费用、权利决定或用户身份操作时暂停相应步骤。某一支受阻，不妨碍继续完成独立的安全步骤。

## 先确定范围，不扩张授权

- 先读项目规则，恢复当前源码、安装版本、构建记录、分支、网站和公开仓库状态；历史成功记录不能代替当前检查。
- 只补问影响结果的缺口：目标平台、发布包、是否公开源码、公开仓库/域名/站点、费用上限、可以上传的素材。已有明确授权不要重复索要。
- “发布 App”“公开 Git”“制作海报”“申请服务器”分别限定到相应目标；不自动开放现有私有仓库、上传工作目录、注册付费服务、改线上 DNS 或替换正式安装。
- **公开源码不等于授予开源许可，免费软件不等于无版权。** 未明确的软件许可保持现状；不能为了分享此技能，把用户软件也改成 MIT。本技能自身的 MIT 不传播到产物。
- 账户注册最终提交、付费/绑卡、身份验证、密钥创建、对外发帖、上传、权限改变等仍遵守当前工具及用户的授权要求。人工验证交给用户，不伪造身份或绕过验证码。
- 敏感 PDF、真实聊天、客户资料、API Key、签名私钥、密钥链、账户导出、个人路径均不进入公开 Git、素材、日志或发布清单；使用自建样本证明功能。不要扫描或回显无关凭证库。

## 按需读取

- 选择或申请境外托管、VPS、子域名/独立域名，配置 DNS / HTTPS 时，读 [free-hosting-domain.md](references/free-hosting-domain.md)。它区分能立即使用的静态托管与可能需审核、绑卡或付费的资源。
- 制作官网、功能页、教程、海报、宣传视频，以及网页/媒体验收时，读 [site-media-qa.md](references/site-media-qa.md)。不要默认给简单更新附加全套宣传工作。

## 执行与验收门

### 1. 建立当前事实与发布边界

检查源码和真实界面，把能力分成可用、有限兼容、未支持、展示/演示。保留来源依据，别从图标或营销文案推断功能。找出外部运行时、绝对本机路径、硬编码地址、联网 Key、字体、编解码器、动态库和系统版本依赖。

在隔离的发布目录按允许清单收集文件，保留脏工作树与用户原始资产。现有 Git 历史可能含私密内容：未审查历史时，不把它直接变公开，也不靠删除当前文件假装历史已清除。新建干净公开镜像通常比改写用户历史更安全，但仍需目标仓库授权。

### 2. 处理依赖和权利

逐项记录原创来源、第三方组件许可证、署名/再分发条件、字体与音视频使用范围。许可证未知或不允许目标分发时，先阻止相应公开内容；选择取得授权、按许可分发、明确移除该能力，或独立实现。

独立实现从可用的公开规格、经授权观察和自建输入推导行为，不复制受限源代码、反编译表达、受保护素材或商标外观来“洗掉许可”。重写不自动证明没有权利风险；有争议时说明具体不确定性，不能宣称法律意义“完全自主知识产权”。

选择原生/可再分发实现时，以原有行为规格做回归：先证明旧路径的依赖或缺陷，再测试替代。拒绝不识别的复杂输入，保留原件；不能把覆盖外观、文本提取成功或栅格截图当成真实对象编辑成功。保留必要的第三方 NOTICE / LICENSE，不声称包内所有组件都属于自己。

### 3. 生成可携带候选并真实测试

- 在明确源码身份上构建；记录提交及脏状态，不能只看包的版本号或修改时间。产物内不得带开发者绝对路径、私有数据、临时代理或用户 Key。
- 检查最终包动态库、辅助进程和资源闭包。需要外置 Python、包管理器或开发环境才能工作的包，不能叫“打开即用”；若有可选外部条件，应逐功能写明。
- 使用目标系统上的实际发布候选测试：启动、打开自建样本、关键操作、保存重开、页面/文字/像素或对象完整性、错误输入与权限拒绝；修改前后原件哈希一致。UI 和后台引擎分别验证，后台测试通过不代表桌面操作无崩溃。
- macOS 可用 `file` / `lipo`、`otool -L`、`codesign --verify --deep --strict`、`codesign -dv` 检查实际候选；只有有权及已具备材料时才运行公证提交。ad-hoc 签名不等于 Developer ID、不等于 Apple 公证，也不保证 Gatekeeper 放行。不要提供关闭全局安全检查的安装方案。
- Windows / Linux 同样按实际架构、系统最低版本、运行库和签名状态说明；未在相应平台运行过，只能报告构建/静态检查，不能宣称跨平台验收。
- 安装到用户正式位置、自动退出/清理旧包仅在用户或项目已有明确授权时进行；正常退出、保留未保存内容，回读新安装身份后才退休旧包。默认保留源码与非可启动归档，不强杀用户应用。

候选通过后再制作 DMG、ZIP、安装器等最终下载文件。**所有会改变包字节的步骤之后**再计算 SHA-256 和大小；对签名、压缩或脱敏前的包算哈希不能证明最终下载包。

### 4. 分别固定软件、源码和站点身份

维护一份不含敏感内容的发布记录，可按项目格式存储；至少能回答：

| 对象 | 独立身份 | 必须回读的证据 |
| --- | --- | --- |
| 软件包 | 版本、构建号、系统/架构、文件名、字节数、SHA-256、签名/公证状态 | 公开下载后重新算哈希，实际启动/保存回归 |
| 对应源码 | 仓库、提交/标签、源归档 SHA-256、与包的对应关系 | 远端提交/标签回读、干净克隆或归档检查 |
| 官网 | 仓库提交或部署 ID、站点 URL、发布来源目录 | Pages/托管部署状态、线上标题/资源/下载链接/媒体 |
| 权利与费用 | 软件授权范围、第三方清单、素材署名、可选收费条件 | 文件/页面一致，不以“免费”代替权利审查 |
| 验收 | 引擎、目标桌面、网页桌面/移动、媒体和用户接受各自状态 | 明确 PASS、FAIL、NOT_RUN、PENDING，不相互替代 |

源码公开镜像可能有路径清理、资源替换或不同提交：如实记录映射与差异。未证明可重现构建时，不承诺源码自行构建与包逐字节相同。网站提交也不必等于软件源码提交，但两者应明确绑定同一发布说明。

### 5. 真正发布，而非只生成文件

确认对应范围获授权后，完成需要的仓库、Release 资产、源码、官网和域名步骤。无需某项时标为不适用，不为静态官网强加 VPS 或购域名。

- 公开 Git：按白名单审查文件与历史；加入用户已确定的软件版权/许可、第三方声明和可复现的构建/使用说明。不要把整个共享工作区推上去；不要擅自选择开源许可证。
- Release：稳定命名并关联正确标签；大安装包按平台适合的资产渠道发布，不把它们塞进静态网站源码。发布说明列出可用能力、限制、系统、签名、费用、哈希和源码对应关系。
- 官网：部署已审核的网站目录，校验项目子路径、相对资源、跨页导航、下载 URL、版本和哈希；权限不足就记录具体缺口，不把本地预览或成功 push 当线上部署完成。
- 网络：先判断 DNS、认证、权限、代理或传输问题。代理仅从当前已授权配置或实际监听状态发现，临时用于本次必要命令；不硬编码用户名/端口、不改全局 Git/系统代理、不把凭据 URL 或代理配置写进技能、仓库和清单。
- 写操作超时后先回读远端：同名仓库、标签、Release 资产或部署可能已经成功。按已完成状态继续，不盲目重复创建，不覆盖已发布的不可变资产。有限重试仍失败时报告具体失败证据与安全的下一步；只有用户要求监测时才设置后续监控。

### 6. 公开回读与交付

从公开 URL 下载最终资产到独立临时目录，核对 SHA-256、大小和预期文件结构；回读远端源码提交/标签。官网需同时取得部署结果与实际浏览器证据，包含桌面和至少一个明确尺寸的移动视口。服务器申请、DNS、TLS、网站业务操作分别验收。

不要把 HTTP 200、截图、视频能播放、单个测试通过、安装成功或用户未回应升级成其他门已通过。浏览器不可用时明确报告静态检查已完成、视觉/移动未验收；不编造截图或发布状态。

交付时给可点击的官网、下载、源码/技能仓库及版本说明；简述实际完成项、哈希/身份、测试范围、费用和剩余限制。只有用户明确把确认设为下一步前提时才等确认，不自行撤销已有发布授权；但新的付费、账户、许可和隐私决定不能代替用户作出。

## 可复用的防错经验

- 功能菜单可能有禁用项；功能页和教程应从真实路由生成说明，禁止把“有卡片”写成“已支持”。
- “存储副本”不一定切换当前文档。防覆盖教程应明确新位置，并要求重新打开副本后练习。
- 原生 PDF 字体/内容替换需分别证明外观、可复制文字、保存重开和原件不变；只看一个维度会漏掉回归。
- macOS 后台任务里的 `Process.waitUntilExit()` 可能驱动线程 RunLoop，引发 PDFKit 通知落入 AppKit 非主线程。涉及这类 UI 时测试实际工作台流程；采用有界且可取消的进程退出等待，并把界面更新留在主线程，不能只凭引擎单测下结论。
- 内置 Web 工作区的存档、桌面原生画布存档和云端项目不是同一份数据；写清备份格式、恢复入口、Key 范围和迁移边界。
- 发布后安装包、对应源码、官网仍可能分别落后；每次都回读三个对象，不拿其中一个的成功为另两个背书。
