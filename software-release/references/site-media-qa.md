# 官网 UI、教程、海报视频与验收

## 从真实功能开始

先核查工具目录、菜单路由、控制器和实际发布候选。为功能记录“真实入口 → 操作 → 输出 → 限制 → 验证状态”。有禁用按钮、仅展示预览、待配置外部服务或有限兼容的项目必须如实标注，不从产品海报反推软件能力。

官网常用结构可按任务裁剪：

- 首页：一句准确定位、真实产品图或明确标注的概念示意、平台与下载入口。
- 功能页：逐项能力、限制和外部条件；禁用工具独立列出。
- 教程：按用户任务给真实步骤，提供目录和交叉链接；写清保存副本、备份格式、恢复入口及撤销边界。
- 下载/版本页：版本、构建号、架构、系统要求、签名/公证、大小、最终资产 SHA-256、对应源码、已知问题。
- 权利/隐私/费用：软件使用许可、第三方声明、媒体署名、本地和联网数据边界、可选服务独立计费。

页面中不要填编造的用户数、下载量、评分、第三方推荐、合规认证或“全面支持”。“免费”应拆成软件费用、托管/域名费用和第三方 API 费用，不承诺无限免费 AI。

## UI 制作与真实内容

- 需要寻找设计基准时，比较少量当前热门项目的实际演示、适用性、许可与维护情况；star 数记日期，不以排名替代产品判断。从层次、排版、节奏和交互学习，独立设计本产品，不复制受保护素材、商标或页面源代码来假称原创。选定方向后进入实现，不无限调研。
- 保持用户已有品牌、获准的海报/视频、字体与版式；请求增加教程不等于授权重做所有视觉。
- 用一致的字体、颜色、空间与组件；标题字体需要正确的授权、实际资源和 font-weight，CSS 写了字体名不等于浏览器已加载。
- 手机布局不是桌面等比缩小：导航可换行，卡片单列，正文有合理边距，表格/代码能滚动；目录和按钮的点击区域应可用。
- 图片写准确 alt，给尺寸并合理延迟加载；视频提供 controls、playsinline、合理 poster 与回退下载链接，不默认带声音自动播放。
- 多页站点和项目子路径优先相对 URL；检查从首页、深层页和直接刷新都能访问。
- 不引入无关统计、第三方登录或远端依赖；本地处理文档不等于可选 AI 永不联网，分别说明发送内容、授权时点和服务商。
- 真实功能教程先在自建样本上操作。尤其说明“存储副本是否切换当前标签”“画布导出是展示还是可编辑存档”“取消生成是否撤销远端任务”。

## 海报：先保权利，再讲产品

用户要求制作时，先确定用途、比例、文案和现有品牌素材，使用可用的图像生成/设计能力并遵守相应技能；没有该能力时可用本地排版生成原创图形，不能谎称已生成真实应用截图。

1. 把文案限定在已验证能力；未测试平台、未获域名、未完成公证不能放成卖点。
2. 截图使用应用真实画面和自建/可公开样本。遮去私人文件名、路径、账户、Key 和客户信息；不要把尚未脱敏的截图交给外部生成服务。
3. 概念渲染或合成文档明确标注“示意 / 非真实截图”；不能让用户以为演示结构就是已完成 UI。
4. 核对图片、字体、图标、商标、摄影、音乐/音效来源。保留必要署名及原始许可，不因生成工具或免费素材而声称无条件拥有全部版权。
5. 输出主版和需要的网页尺寸，检查中文缺字、裁切、对比度、移动端小字和下载按钮；不得为了排版删除关键限制。

用户指定保留原版海报时，不在未经批准的情况下重新生成替代。仅有文件存在或技术可解码，不能证明其权利已清楚。

## 宣传视频：工程验证与内容验收分开

用用户批准的素材制作适合渠道的故事板；时长、比例和清晰度按要求，不能把某次项目的“30 秒/9:16”固化为所有任务标准。带真实操作演示时注明必要条件；不把演示动画当作全部功能测试。

建议验证项：

1. 播放首帧、中段、末帧及关键操作段，检查黑帧、字幕、中文字体、画面跳变、剪切和误导文案。
2. 用可用媒体工具读实际时长、分辨率、帧率、音视频轨道与编码；元信息不等于观看验收。网页交付选兼容编码并实际在浏览器播放。
3. 用户要求保留原音时保留，并比较源/输出；音频缺失不能靠网页 controls 假装存在。新配乐必须有适用权利，使用付费/外部生成 API 前确认费用与上传范围。
4. 检查静音、音量、口播和字幕同步；不在未试听时报告“声音正常”。
5. 输出 MP4 等交付文件和合适网页资源，回读最终 SHA-256。大视频使用合适分发渠道，避免让 Git 历史或 Pages 配额被无必要的大文件占满。
6. 旧素材仍被网页引用时，部署前同时检查实际文件与引用；不要只替换封面而把旧视频继续当最新版。

缺少播放/录音或渲染能力时，交付可验证的部分并报告未运行项。不得编造已试听、已观看或已获用户接受。

## 上线前与上线后检查

### 静态/构建检查

- 所有本地链接、资源、跨页锚点与下载链接存在；无重复 ID、错误大小写、未关闭标签、源码中的本机路径和凭证。
- 主要页面的版本、大小、哈希、架构、源标签一致；不把开发候选/预览链接当正式版本。
- 功能页的可用、有限兼容与禁用项对应实际目录；教程按钮名称与现有界面一致。
- 无脚手架占位、假 API、未授权统计；许可证、素材出处和费用声明齐全。

### 浏览器检查

使用当前环境允许的浏览器控制方式。至少记录一个明确的桌面视口和一个移动视口的宽高；一个手机尺寸不等于“全设备通过”。

请求设置视口后回读实际布局宽高；工具接受了 390px 参数但页面仍是桌面宽度时，不计作手机验证。明确区分本地预览与公网部署的浏览器结果。

实际检查：导航、目录跳转、长标题换行、字体加载、横向溢出、按钮、下载目标、图片、视频首屏和播放、键盘焦点。长页面除首屏还看中段/底部；只看到截图不能代替点击下载、跨页打开与视频播放。

字体 `font-family` 解析正确、网络请求成功及实际渲染分别检查；无法确认时不把 fallback 当品牌字体验收。没有浏览器就只报告静态/HTTP 检查，保留视觉状态 NOT_RUN。

### 线上回读

1. 取得真实部署记录/提交，再打开公开 URL，检查标题、关键内容与最新资源。push 成功不等于 Pages 构建或发布成功。
2. 从官网的实际按钮下载最终包，独立重算 SHA-256；避免只访问手写的 Release URL 而遗漏网页仍指旧包。
3. 分别记录源提交、站点提交/部署、发布资产哈希。CDN 或浏览器缓存可能导致部分内容新、部分旧，需要检查资源实际响应而不是无限刷新。
4. 看桌面和移动浏览器的线上默认视图；本地响应式样式通过不等于线上视觉通过。
5. 检查广告/演示文案没有超过本轮功能证据，且费用/隐私/未支持项在用户决策前能看到。

## 可分享的发布回执

回执使用相对文件名、公开 URL、提交 ID、哈希、时间与验收范围，不含私人路径、账户标识或真实文档内容。推荐最小字段：

```json
{
  "software": {"version": null, "build": null, "sourceCommit": null, "artifactSHA256": null},
  "source": {"publicURL": null, "publicCommit": null, "archiveSHA256": null, "licenseScope": null},
  "website": {"url": null, "commitOrDeployment": null, "onlineReadback": "NOT_RUN"},
  "acceptance": {"engine": "NOT_RUN", "desktopApp": "NOT_RUN", "webDesktop": "NOT_RUN", "webMobile": "NOT_RUN", "media": "NOT_RUN", "user": "PENDING"}
}
```

上例是未运行状态，不是发布证明；实际交付必须填写已取得的值或明确解释不适用/受阻。用户接受不能从工程测试自动推断；用户未要求等待确认时，也不把 PENDING 擅自变成阻止已获授权发布的新条件。
